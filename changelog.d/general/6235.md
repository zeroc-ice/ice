- The invocation timeout and locator cache timeout are now normalized consistently in all language mappings and at
  all configuration surfaces: the `ice_invocationTimeout` and `ice_locatorCacheTimeout` proxy methods, the
  per-proxy `InvocationTimeout` and `LocatorCacheTimeout` proxy properties, and the `Ice.Default.InvocationTimeout`
  and `Ice.Default.LocatorCacheTimeout` properties. An invocation timeout of zero or any negative value means
  infinite and is normalized to -1. Any negative locator cache timeout means infinite and is normalized to -1,
  while 0 still means no caching. In the proxy methods, a positive timeout that is not a whole number of the
  corresponding property's unit (seconds for the locator cache timeout, milliseconds for the invocation timeout) is
  rounded up to the next whole number, and a timeout greater than 2147483647 of this unit is rejected with an
  exception. Previously, a fractional timeout was silently truncated by the duration-typed overloads in C++ and
  Java, and produced a proxy property value (such as `LocatorCacheTimeout=1.5`) that `propertyToProxy` rejected in
  C# and JavaScript.
