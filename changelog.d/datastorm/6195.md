- A node now serializes the client thread pool of the communicators it creates. A node depends on the requests it
  receives on a connection being dispatched in the order they were sent, and the sessions carried by a connection
  the node opened are dispatched on that pool; previously they were ordered only because the pool holds a single
  thread by default. The setting has no effect on a single-threaded pool, and the `Node(argc, argv)` constructor
  applies it as a default, so an application that configures `Ice.ThreadPool.Client.Serialize` itself keeps its
  own value. A communicator supplied to a node is left untouched and must be configured for ordered dispatch
  before it is created.
